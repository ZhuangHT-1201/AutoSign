# 架构说明

## 总览

```text
React 界面
    │
    ├── 课表与签到业务逻辑（src/services）
    ├── 数据解析与 WebVPN 转换（src/lib）
    │
    └── 原生桥接
          ├── Electron：受控 IPC + Chromium 会话
          └── Android：Capacitor 插件 + WebView Cookie
```

桌面端与安卓端共享 React 页面、数据模型和解析逻辑。原生层只负责三件事：

1. 打开学校官方认证页面。
2. 使用与认证页面共享的 Cookie 发起受限 HTTP 请求。
3. 清理本地校园会话。

因此项目没有自建网关，也不会把用户会话上传到项目方服务器。

## 连接模式

### 自动

首次登录前探测本科教务直连地址。可达时使用校园直连；无法连接时使用学校 WebVPN。

### 校园直连

请求直接发往学校域名，适合校内网络或允许直连的网络环境。

### WebVPN

客户端将目标域名编码到学校 WebVPN 路径中。认证、Cookie 与重定向仍由学校服务处理。

## 课表

1. 获取学期列表。
2. 获取周次列表并按日期定位当前周。
3. 获取所选周课程。
4. 若本科门户不可用，则尝试研究生课表服务。
5. 将排课字段规范化为统一 `Course` 模型。
6. 最近一次成功结果保存在本机。

## 签到

签到分为三层：

1. 通过已登录的统一认证会话获取课堂服务登录信息。
2. 查询当天签到课程及状态。
3. 用户点击后获取服务端时间并提交本人签到。

写操作只向当前账号对应的课程提交，不进行后台轮询或自动代签。

## 安全边界

- 桌面端只允许访问代码中声明的校园域名。
- 认证窗口不加载应用 preload，不暴露 Node.js。
- 渲染进程启用上下文隔离，禁用 Node 集成。
- 外部链接使用系统浏览器打开。
- Android 原生网络插件只允许 HTTP/HTTPS。
- 请求正文不写入日志。
